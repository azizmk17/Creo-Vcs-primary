# Snapshot backup and cleanup

Choose **Snapshot and Clean…** and select a backup folder on the backup disk that the project team can access. Nexus copies the root Creo files and eligible closed commit, approval and sealed snapshot Creo files, verifies the copies, and records the snapshot and backup location before cleanup. The progress dialog reports the active copy, verification or cleanup operation. Snapshot details show the files removed and the location of the backup. `cleanup.jsonl` in the backup records each attempted removal and its result.

The latest verified validated iteration and the current Master file stay in the project. If a newer unvalidated iteration is current in Master, it is retained as well. Nexus records the highest iteration number before cleanup, so subsequent Nexus publications do not reuse archived iteration numbers. When an Item points to an older file and a newer validated replacement of the same Creo name can be verified, Nexus updates the current Item reference and records the change in the snapshot. It does not change references for Items with pending work, checkouts, or active or paused branches, and it does not guess when validation cannot be verified. Pending submissions, branches, deliverables, files shared with unfinished work, and incomplete approval journals are retained. Unrecognized historical locations are left alone. Open or changed files are skipped; on Windows the application obtains an exclusive file handle and rechecks the bytes against the verified backup before deletion. Directories made empty by cleanup are removed without deleting the project root. Skipped files and Item reference changes are listed in the snapshot details. Rerun a snapshot after files are closed if needed.

When a captured root iteration or archived commit Creo file is opened from the BOM or commit folder, Nexus identifies the snapshot and backup path. Keep the backup disk and snapshot record available to everyone who needs historical versions. The backup is not a database backup and the application does not configure network permissions. The cleanup is scoped to the current project; it does not remove branch workspaces or delivered PDF/STEP files.

For best results close Creo and finish active file operations before cleaning. A database write lock protects the cleanup decisions while files are removed. Interrupted operations preserve the backup and the cleanup journal; snapshot details can show an interrupted state. Check the journal and the source and backup locations before retrying.
